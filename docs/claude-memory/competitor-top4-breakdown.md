Why "Give more than 100%" feels SEAMLESS start to end (studied at 4 fps, 2026-11-08): (1) it opens on the PAYOFF image (a winner
on a podium, instantly readable) and at 2 s the camera PANS DOWN the ladder into the hidden building of struggle — one continuous
move, no cut; (2) every scene is a PROCESS that animates the whole time (a line drawing itself: expectation straight, reality
zig-zag; chains being hauled up; sliders rising) so there is never a still moment; (3) dips to black are very short (~0.5 s) and
each next scene starts already moving; (4) one visual system all through (white pictograms, black, same thin labels, rows reused
in the same layout) so the eye never re-orients; (5) scenes of even length ~5–6 s.

Common grammar: 5–6 vignettes in 32–36 s; every vignette is TWO (or three) LABELLED options doing the SAME physical task at the
same time; one option looks easier/faster first, then the cost shows; a counter or a meter; one cutaway/camera reveal; plain words.
Their hooks are literal and readable at frame 0 (two labelled figures + one object).
**How to apply:** build every script on this grammar but with our own mechanics; check against [[competitor-format]] used-ideas.
